Dev notes

I wanted a Solana supply whose unit meant something before anyone traded it. One bitcoin is divided into exactly one hundred million sats. Pinning the supply rule to that denomination gives every remaining token a number that can be recomputed instead of a story that has to be trusted.

The first decision was that supply only falls. Dust is burned instead of carried, mint authority is removed and every replayable proof is marked as spent. The mechanism has no path that expands supply.

The second decision was that cross-chain state changes must begin with Bitcoin evidence, not an admin button. A settlement is a public Bitcoin transaction, a 32-byte commitment, a Merkle branch and enough proof of work. Relayers transport evidence; they do not grant permission.

The Bitcoin header chain is the cost of that decision. Merkle inclusion is meaningful only when the referenced header belongs to the best-work chain. Six confirmations make settlement slower than a normal Solana instruction, deliberately exchanging latency for verifiable Bitcoin finality.

The interface reads the Solana market every second, refreshes fills every fifteen seconds and reads the tracked Bitcoin tip once per minute. Market data drives the readout; Bitcoin headers and Merkle proofs drive settlement. The two paths never substitute for each other.

Nothing on the site is a sample. If a value is blank, the input has not arrived. I would rather you see an empty cell than a number I made up, because a made up number on a page about enforcement would be the one thing that disproved the page.

The front page is a preprint abstract because that is the form in which a claim is made and then left alone to be checked. The sidebar reads the market because an abstract about a live object should have the object next to it.

Bitcoin orange marks commitments, canonical headers and audit links. Black is the working surface. Green and red are reserved for directional market changes; color never changes protocol meaning.

The mark is intentionally reduced to a black block and two white strokes on Bitcoin orange. It identifies the protocol without competing with the numerical readout.

The dev panel exists only on the preview. On the published domain there is no way to change the mint and no way to change anything else. The site is a readout, and a readout with a knob is a different kind of object.

I computed the reserve from the fee rate and the fill volume because the program's actual reserve account is not something a site should guess at. The site says what it computed and how. The account says what is true.

If you read this far you have read more about a supply than the supply will ever read about you. That asymmetry is the point.
